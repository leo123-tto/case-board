save_local_kb_material — 把一份具有长期复用价值的完整法律材料新增到本地知识库 L1 raw 层。只有用户在本轮明确要求“保存到知识库、入库、沉淀供以后复用”，或者外部付费检索已经取得完整法规、完整案例、完整实务文章而系统规则明确要求写回时，才可以调用。普通问答、临时草稿、推测性总结、搜索结果列表、只有标题的空壳、接口日志、报错页、重复内容不得调用。

本工具只允许四种 material_type：regulation（完整法规或规范性文件正文）、case（完整裁判文书或完整权威案例正文）、article（完整实务文章或研究材料）、note（其他完整或近完整的法律笔记）。title 必须是真实标题；content_md 必须保留足以核验和后续检索的正文，不能为了省上下文只写几句摘要；source 应尽量写明来源网站、发布机关、案号、链接、用户提供或检索日期等可追溯信息。不得虚构来源、时效、案号、法规名称或正文。

material_type=regulation 时必须保留真实时效标签，不得为了入库删除或篡改。现行或未标注材料按 `current_or_unspecified` 写入；明确标注失效、废止、尚未生效或未生效的完整法规只可按 `historical_research_only` 写入 L1 raw，默认现行法关键词检索和向量索引会排除，不能冒充当前依据。

安全边界由 CaseBoard Rust 宿主强制执行，Native 与 Pi Runtime 完全相同：设置中的“允许内置 AI 新增 L1 raw 材料”默认关闭，关闭时不得反复尝试；开启后也只能 create-only 写入 `<知识库>/raw/notes/`，文件名经过安全化并带正文哈希，同一正文不会重复写入。工具不接受任意路径，不允许覆盖已有文件，不允许删除、移动、批量改名，不允许写 `wiki/sources`、`wiki/topics`、`00_ARCHIVE` 或案件原文件，也不会自动把 L1 宣称为 L2/L3。

成功结果会标记 `kb_level: L1` 与 `wiki_status: pending_review`。这表示材料已经可以进入 raw 关键词检索，并可在 embedding 配置有效时进入增量向量索引；它仍需人工复核来源、完整性、版本和时效，才能另行建设 Wiki 导航卡。法规引用时仍必须核对现行有效版本和具体法条，案例引用时仍必须回到完整裁判文书。若工具返回“相同正文已存在”，直接复用本地材料，不要换标题制造重复副本。
