## 操作 SOP

**加新需求**:
1. 简要写清楚:用户故事 + 期望行为
2. 标优先级
3. 加到对应优先级表格,状态 `💡 idea`
4. 调研后改状态为 `🔍 researching` 或 `📐 designing`
5. 写代码前**先在 upstream 开 issue 讨论**(大改动)
6. 开 PR 后状态改 `🔵 pr-submitted`
7. 合并后挪到 `Done`

**优先级调整**:
- 每月 1 号复盘一次
- 用 P0/P1/P2/P3 + 状态两个轴重排

**大改动的设计 doc**:
- 放在 `docs/design/<FEAT-ID>-<short>.md`
- 至少回答:用户故事 / API 变化 / 风险 / 测试策略

## 灵感来源(随时记)

- 自己在用 App 时发现的不便
- 上游 issue 里的 `feature_request`
- 同类工具(法律科技)的对照
- 律师群体的反馈
- 国家政策 / 法规变化带来的新需求

记下来后丢进 `💡 idea` 表格,定期复盘决定要不要做。
