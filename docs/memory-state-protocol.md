# 记忆与状态管理协议

## 设计理念

对标 MemPalace（原文存储 + 时序实体关系图 + 空间索引）+ Ruflo（自适应记忆 + resume_pack）+ Shepherd Session Manager（断点续跑）。

核心原则：**让检索层负责理解，而非让存储层负责摘要**。

## 记忆分层体系（四层模型）

| 层级 | 名称 | 存储位置 | 内容 | 生命周期 |
|---|---|---|---|---|
| L1 Working | 工作记忆 | 当前会话 + `cases/<案号>/STATUS.md` | 当前门禁/进行中/阻塞 | 会话内 |
| L2 Episodic | 案件记忆 | `memory/` + `cases/<案号>/outputs/` | 全部门禁产物/审计日志/关键决策 | 案件生命周期 |
| L3 Semantic | 知识记忆 | `references/` + `rules/` + `skills/` | 法律规则/类案裁判/技能知识 | 持续更新（季度 Compaction） |
| L4 Procedural | 程序记忆 | `rules/` + `gates/` + `checklists/` + `agents/` | 门禁流程/重复失败模式/最佳实践 | 持续演化 |

## 记忆注入协议（会话启动自动执行）

### 第 0.5 步：期限快速扫描
- `docket-watcher` agent 自动扫描全部在办案件程序期限
- ≤7 天 → 紧急标记红色；≤30 天 → 预警标记橙色
- 无紧急项则静默跳过

### 第 0.7 步：Gate 0 自动触发判定
满足任一条件时强制触发任务说明书：
- ≥3 份独立材料 / ≥2 个法律领域交叉 / ≥2 类文书产出
- 律师明确表达「复杂」「多步」「分阶段」意图
- 预估提取条目 ≥100 条

### 第 1 步：上下文恢复 + 断点续跑
```
读取 STATUS.md + 审计日志 + state.json
→ 定位上次退出原因（超时/中断/错误/正常结束）
→ 生成断点续跑状态块：
  【断点续跑状态】
  - 上次运行：{时间戳}
  - 退出原因：{会话超时/用户中断/Agent错误/正常结束}
  - 已完成：{已通过钩子的门禁列表}
  - 进行中：{正在执行但未通过钩子的门禁}
  - 待重试：{回退但未达3次上限的门禁+具体失败原因}
  - 待办项：{从 TASKS.md 匹配的待办}
→ 注入系统提示（≤800字）
```

### 第 2 步：语义匹配
在 `memory/` 下搜索相关历史条目：
- 优先级：同案号 → 同类案由 → 同门禁阶段 → 通用经验（recurring_errors.md）

### 第 3 步：自动注入
匹配到的记忆条目录格式化为「记忆注入块」追加到系统提示

### 第 4 步：会话存档
每次门禁钩子通过后，在 STATUS.md 追加阶段产物索引：
```
| 时间 | 门禁 | 状态 | 产物路径 | 关键摘要 |
```

## 原文存储纪律

| 记忆类型 | 存储方式 |
|---|---|
| 律师决策/指示 | 原文存储——保留律师原话表述，不精炼、不意译 |
| 案件关键事实 | 原文 + 来源锚点（文件+页码） |
| 工作流决策 | 原文存储——保留决策时的完整上下文和理由 |
| AI 分析结论 | 标注「AI生成」——区分事实与 AI 判断 |
| 法规/判例引用 | 原文附版本日期 + 现行有效性标注 |

## 事实时效性标注

| 标注 | 含义 | 触发条件 |
|---|---|---|
| `[有效: YYYY-MM-DD]` | 基于当时有效的法规/数据 | 初次写入 |
| `[待复核: YYYY-MM-DD]` | 接近 90 天新鲜度窗口 | 距分析日期 ≥80 天自动升级 |
| `[已过期: YYYY-MM-DD]` | 法规已修订/判例被推翻 | 经核验确认过期后标注 |

## 话题交叉索引

每个案件 STATUS.md 维护话题级索引：

```markdown
| 话题 | 涉及门禁 | 本案关键文件 | 关联案件同话题 |
|---|---|---|---|
| 合同效力认定 | Gate 1/2/3 | outputs/01/..., outputs/03/... | [[案号]]#合同效力 |
| 违约责任 | Gate 1/2/3/4 | ... | — |
```

## 自学习反馈闭环

```
同一类型失败在审计日志中出现 ≥3 次
  → 自动提取失败模式
  → 写入 memory/recurring_errors.md
  → 后续同类任务记忆注入自动加载
  → 在任务启动时预防重复错误
```

## 案件进展可视化简报（五层展开）

每次门禁钩子通过后自动输出：

```
🎯 当前目标 → 📋 目标分解 → 📊 各阶段状态 → 🚧 当前阻塞项 → 👉 下一步行动
```

## 审计日志格式

每次门禁完成后追加：
```
[YYYY-MM-DD HH:MM] Gate{N}-{阶段名} | 模型: {模型} | Token: {消耗} | 产出条目: {N} | 漂移: {无/N项} | 遗留: {N项待处理}
```

每次 Skill 触发时追加：
```
[Skill] {skill-name} | 触发条件: {关键词/门禁阶段} | 结果: {成功/失败/未触发}
```

## 跨会话案件进度看板

从审计日志 + `state.json` 生成结构化进度摘要：

```text
## 案件进度看板（{生成时间}）
| 案件 | 当前门禁 | 完成条目 | 完成率 | 下一个人工操作 | 距期限 |
| {编号} | Gate {N} | {DONE}/{TOTAL} | {X}% | {审查提取表/批准推理结论/最终审阅文书} | {天数}天 |
```

## 定期维护（季度 Skill Compaction）

每季度清理检查：
1. 合并跨规则的重复表述
2. 删除长期（>90天）未被引用的规则
3. 下沉过度展开的细节（>500字）到 references
4. 识别 ≥3 次的同类失败模式→提取为规则更新建议
