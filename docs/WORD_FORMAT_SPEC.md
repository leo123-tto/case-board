## 〇、规范的来历（为什么不是"差不多就行"）

法律文书区别于一般文档的关键是**小问题会被无限放大**。md2word-gate 第一次实跑 `202606_周世文超龄用工合同_审查报告.docx`，抓出 42 处半角标点——肉眼根本看不出来，但发出去就是"不专业"。

文格的口诀：

> **能执行的执行。能检查的检查。能证明的证明。证明不了的地方，直接报告给人。**

规范的本质：**把"差不多"变成"可校验"**。

## 一、页面与版式

| 项 | 规范值 | 备注 |
|---|---|---|
| 页面尺寸 | A4（11906 × 16838 twip） | 纵向 |
| 页边距 | 上下左右各 1440 twip（1 英寸） | 法院文书惯例 |
| 页眉/页脚区 | 距边 708 twip（0.5 英寸） | 给页眉页脚留位 |
| docGrid linePitch | 360 | 1.5 倍行距配套 |
| 默认行距 | 1.5 倍（`w:line=360 w:lineRule=auto`） | 报告档与法律文书档一致 |
| 默认对齐 | 两端对齐（`w:jc=both`） | 文书标题例外：居中 |
| 默认缩进 | 正文首行缩进 2 字（560 twip） | 文书标题与表格内段落不缩进 |

**横排 A4**（仅"多列大表格"场景使用，按 VB-word 横表自适应）：

- 纸张旋转为 `w:orient=landscape`，宽 16838 × 高 11906
- 边距 25mm
- 表格宽度按内容自适应，超出可用宽度则等比压缩至可用宽度

## 二、字体配比（核心 · 法律文书灵魂）

**双字体 inline rPr**——同一 `<w:r>` 上同时声明 `w:ascii` 与 `w:eastAsia`，这是被废弃的 macOS `textutil` 路径结构上做不到的，**必须保留**。

| 角色 | eastAsia | ascii | 字重 | 适用 |
|---|---|---|---|---|
| 文书标题 | 方正小标宋简体 | Times New Roman | 默认 | 居中大字标题 |
| 一级标题 | SimHei（黑体） | Times New Roman | 默认 | H1 / H2（base 档） |
| 二级标题 | SimHei（黑体） | Times New Roman | 默认 | H3+（base 档） |
| 正文 | 仿宋_GB2312 | Times New Roman | 默认 | 段落 / 列表 / 表格 |
| 强调正文 | 仿宋_GB2312 | Times New Roman | 加粗 | 段内 `**加粗**` |
| 行内代码 | Songti SC | Menlo | 默认 | Editor 档专用 |
| 预格式块 | Songti SC | Menlo | 默认 | Editor 档专用，浅灰底 F3F4F6 |

**字号表**（半点单位）：

| 角色 | Base / Filing | Editor |
|---|---|---|
| 文书标题 | 32 (16pt) | 34 (17pt) |
| 一级标题 | 30 (15pt) | 34 (17pt) |
| 二级标题 | 28 (14pt) | 28 (14pt) |
| 三级标题 | 28 (14pt) | 26 (13pt) |
| 正文 | 28 (14pt) | 24 (12pt) |

## 三、页眉（必备 · 当前缺失）

**任何对外发送的 .docx 必须有页眉**。

格式约定：

```
左：[机构名]  ·  [案件名/文书名]        右：第 X 页 / 共 Y 页
```

OOXML 实现要点：

- `word/header1.xml` 独立部件，在 `word/_rels/document.xml.rels` 注册关系
- `word/document.xml` 的 `<w:sectPr>` 引用 `<w:headerReference r:id="rIdN" w:type="default"/>`
- 三个字段（机构、案件名、页码）用 `<w:fldSimple>` 或 `<w:fldChar>` 实现，**不硬编码文字**
- 页眉底加分隔线（`<w:pBdr><w:bottom .../></w:pBdr>`），与正文拉开
- 字体：小五号（18 半点），eastAsia=仿宋，ascii=Times

---

## 四、页脚（必备 · 当前缺失）

**任何对外发送的 .docx 必须有页脚，含页码字段**。

格式约定：

```
                    第 [PAGE] 页 / 共 [NUMPAGES] 页
```

OOXML 实现要点：

- `word/footer1.xml` 独立部件，注册关系同上
- **必须用 `PAGE` 字段，绝不硬编码数字**——文格/法院对"页码硬编码"零容忍
- 居中对齐
- 字体：小五号（18 半点），同页眉

字段实现（推荐用 fldSimple）：

```xml
<w:p>
  <w:pPr><w:jc w:val="center"/></w:pPr>
  <w:r><w:rPr><w:rFonts w:ascii="Times New Roman" w:eastAsia="仿宋_GB2312"/><w:sz w:val="18"/></w:rPr><w:t xml:space="preserve">第 </w:t></w:r>
  <w:fldSimple w:instr="PAGE"><w:r><w:rPr>...</w:rPr><w:t>1</w:t></w:r></w:fldSimple>
  <w:r>...<w:t xml:space="preserve"> 页 / 共 </w:t></w:r>
  <w:fldSimple w:instr="NUMPAGES"><w:r>...<w:t>1</w:t></w:r></w:fldSimple>
  <w:r>...<w:t xml:space="preserve"> 页</w:t></w:r>
</w:p>
```

## 五、段落规则

| 规则 | 规范值 | 说明 |
|---|---|---|
| 段前 | 0 | 文格四原则之"少加花样" |
| 段后 | 0 | 同上 |
| 行距 | 1.5 倍 | base / filing / editor 三档统一 |
| 首行缩进 | 2 字（560 twip） | 文书标题、列表项、表格内不缩进 |
| 软换行（行末两空格 + 回车） | 并入同段 | filing 档强制并段；base 档可选 |
| 硬换行（`\n\n`） | 起新段 | 三档一致 |
| `---` 分隔线 | base 档渲染成下边框段；filing 档丢弃 | 贴合报告 vs 文书惯例 |
| 空段 | 全部丢弃 | 防止空行污染 |

## 六、列表规则

| 类型 | Base 档 | Filing 档 | Editor 档 |
|---|---|---|---|
| 有序列表 | "1. " "2. " "3. " 内联文本 | 同 base | 同 base |
| 无序列表 | "• " 内联 + 左悬挂缩进 | 不加圆点 + 段落缩进 | "• " + 缩进 |
| 嵌套深度 | 左缩进 420×depth + 280twip，悬挂 280twip | 普通段落处理 | 同 base |
| 列表项字体 | 仿宋 14pt | 仿宋 14pt | 宋体 12pt |

**判定：报告用 base（带圆点），法律文书用 filing（去圆点、贴法院惯例），可视化编辑器用 editor**。

## 七、表格规则

| 项 | 规范值 |
|---|---|
| 边框 | 全六向（top/left/bottom/right/insideH/insideV）单线 4 半号（0.5pt）黑色 000000 |
| 文字区宽 | 11906 - 1440×2 = 9026 twip |
| 列宽分配 | 9026 / 列数，等分（不做"按内容自适应"，避免列宽抖动） |
| 单元格段落 | 仿宋 14pt，不首行缩进，左对齐 |
| 表头 | 加粗，base 档默认白底；editor 档浅灰底 F4F4F4 |
| 表后空段 | 末块是表格时补一个 `<w:p/>`（OOXML 要求） |
| 单元格填充 | base/filing 留白；editor 表头 F4F4F4 |

## 八、中文标点全角化（导出 Word 静默执行）

**核心防线**：法律文书的半角标点是肉眼看不见但放大镜可见的硬伤。导出时静默修复。

规范策略（保守版，借鉴文格 audit_text 自动版）：

| 标点 | 触发条件 | 替换为 |
|---|---|---|
| `,` | 前后都是 CJK | `，` |
| `.` | 前后都是 CJK | `。` |
| `;` | 前为 CJK | `；` |
| `?` | 前为 CJK | `？` |
| `!` | 前为 CJK | `！` |
| `:` | 前为 CJK 且后非数字 | `：` |

**不自动转**：

- 数字小数点 / 千分位（`3.5` / `1,000`）
- 英文时间（`3:30`）
- 案号里的字母数字（`（2026）苏01民终123号`）
- 括号与引号（涉及配对与英文语境，**保守不碰**）

实现位置：`docx_filing.rs::normalize_cjk_punct`（已实现，V0.3 沿用）。

## 九、Markdown 语法 → OOXML 角色映射

| MD 语法 | 角色（Base/Filing） | 角色（Editor） |
|---|---|---|
| `title` 参数 | 文书标题（居中） | 文书标题（居中） |
| `# H1` / `## H2` | 一级标题（黑体 15pt） | 一级标题（17pt） |
| `### H3+` | 二级标题（黑体 14pt） | 二级/三级标题（13pt/13pt） |
| 普通段落 | 正文（仿宋 14pt） | 正文（宋体 12pt） |
| 列表项 | 正文 + 圆点/编号（base 圆点/filing 去） | 正文 + 圆点/编号 |
| `---` | 下边框段（filing 丢） | 下边框段 |
| `**加粗**` | 该 run 加粗 | 该 run 加粗 |
| GFM 表格 | 仿宋正文表格 | 宋体正文表格，表头浅灰底 |
| ` `` `` 围栏代码 | 不支持（Editor 档→预格式块） | 预格式块（浅灰底 F3F4F6） |
| 行内 `code` | 仿宋等宽不混排 | Menlo 浅灰底 |
| `<!-- 注释 -->` | 整段剥掉 | 整段剥掉 |

## 十、跑前 strip（输入清洗）

导出前**必须**对 MD 做三件事：

1. **剥 HTML 注释**：`<!-- ... -->` 整段丢掉（artifact MD 头部带 `<!-- filing · ... -->`，本模块已有 `extract_filing_title` 解析；其余全剥）
2. **去重正文标题**：若正文首块 H1 与 `title` 参数同名，丢掉（LLM 经常重复）
3. **剥纯星号 run**：`Event::Text("*")` 全部丢弃（pulldown 对 CJK 紧邻的 `**` 不识别，会漏出 `**` 字面量）
4. **元信息抬头**（仅案件分析报告档）：在标题与正文之间补案号 / 受理法院 / 当前状态 / 案件速览，格式 `**案号:**(2026)苏01民终123号`

## 十一、跑后 Gate（交付前门禁 · 必备）

**所有"对外发送"路径必须跑门禁**。门禁的实现参考 md2word-gate，9 项检查：

| # | 检查项 | 实现方式 | 严重度 |
|---|---|---|---|
| 1 | OpenXML 结构完整性 | zip 解压 + 检查关键 XML 部件存在 | FAIL |
| 2 | 页眉存在性 | `word/header*.xml` 是否存在 | WARNING |
| 3 | 页脚页码字段 | `word/footer*.xml` 存在 + `PAGE` 字段 | FAIL |
| 4 | 标题样式引用 | 检测 `<w:pStyle w:val="Heading1"/>` 或 inline rPr | WARNING（法律文书豁免） |
| 5 | 表格边框 | 扫描 `<w:tblBorders>` 是否六向齐全 | FAIL |
| 6 | 字体合规 | 扫描 `w:rFonts w:eastAsia` 必须是仿宋/黑体/方正小标宋之一 | FAIL |
| 7 | 中文标点全角 | 扫描 `w:t` 内容是否含半角标点混入 CJK | FAIL |
| 8 | 空段检测 | 扫描连续 `<w:p/>` 数量 | WARNING |
| 9 | 字符数与段落数统计 | 输出元信息 | INFO |

**退出码**：

- 0：全部通过 → 可对外发送
- 1：仅警告 → 人工复核后发送
- 2：有失败 → **必须修正后重新生成**
- 3：文件错误 → 检查文件路径/格式

**位置**：作为 Rust 模块 `src-tauri/src/docx_gate.rs`，在 `build_docx_bytes` 之后调用；前端可读报告决定是否阻断导出。

## 十二、降级路径（生产级底线）

文格 5 大教训之第 4 条：**降级路径是生产级系统的底线**。

CaseBoard 当前实现已是纯 Rust + 零外部依赖（编进二进制），但还要考虑：

| 失败场景 | 降级方案 |
|---|---|
| Rust 编译失败 | 退回 `textutil` HTML→DOCX 路径（已废弃，但保留应急） |
| Gate 检查失败 | 报告给人，**不阻塞导出**（用户选择是否修正） |
| 页眉/页脚部件失败 | 退回无页眉页脚的 docx（标 WARNING，不阻塞） |
| 字段渲染失败 | 退回硬编码数字页码（标 WARNING） |

---

## 十三、隐私铁律（与 AGENTS.md `PRIVACY_IRON_RULE.md` 联动）

**绝对不在导出的 .docx 中带真实案件数据**——但 MD 源文件本身可能含，导出前必须：

1. **元信息抬头只放公开信息**：案号 / 法院 / 状态可入 Word，**当事人姓名 / 身份证 / 住址 / 银行账号**全不入
2. **测试 fixture 用占位符**：`{{PLAINTIFF}}` / `{{DEFENDANT}}` / `{{CASE_NO}}`（文格的 `{{CASE_NO}}` 字段化模板思路）
3. **不向 LLM 提交完整 .docx**：本模块是纯本地生成，**不进任何 LLM 上下文**
