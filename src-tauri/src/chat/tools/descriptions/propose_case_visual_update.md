为已有的案情可视化工作区提交一份“AI 更新提案”。本工具不会直接覆盖当前图谱，而是把节点、关系、数据集和视图的领域补丁保存为 pending proposal，交给用户在工作台审阅。用户可以只接受其中一部分，人工锁定字段永远优先，当前修订变化后旧提案会自动失效。

调用前必须已取得用户对本轮可视化更新的明确同意：用户本轮直接要求更新、补画或重做相关图表，或者用户回答了可视化多选 ask_user 并选择了具体视图。未经同意不得调用；用户选“暂不生成”或明确拒绝时必须停止。不能用普通对话里的泛泛讨论冒充同意。

补丁必须基于当前工作区 revision，并复用现有节点、关系、数据集和视图的稳定 id。upsert 表示新增或修改，remove 只放明确应删除的 id。不得把整张图无差别重建，否则会破坏律师手工布局、备注与锁定字段。修改材料依据、事实状态、日期、金额或主体关系时，仍须附真实 source_refs；不得把我方主张、对方主张、争议事实或 AI 推断改成 confirmed。

只允许白名单 CaseGraph 字段。不得提交 JSON Patch 路径、HTML、SVG、脚本、远程 URL、图片地址、任意 ECharts option 或 React Flow 配置。确切日期写 date，不完整日期写 date_label。数据集列必须先声明，行内不得出现未声明列，数值不得伪造。补丁 summary 用律师能理解的短句概括本次变化。

如果工具提示 revision 已变化，应先取得最新工作区再重新计算，不能反复提交旧补丁。工具成功只表示提案已保存，不表示变更已生效；回复用户时明确说明“已有待审阅更新”，引导其进入工作台核对新增、修改、删除、来源变化和与人工确认冲突的项目。
