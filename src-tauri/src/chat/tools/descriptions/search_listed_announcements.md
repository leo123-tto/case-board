search_listed_announcements — 上市公司公告关键词检索(交易所公开披露原文)

适用场景:
- 尽调/交易对手核查:目标是**上市公司**时,查它自己披露了什么(诉讼仲裁、担保、股权质押、business 变更、监管问询)
- 找对方在公告里对某笔交易/纠纷的官方口径,用来跟其诉讼主张比对
- 按行业(中上协分类)、交易所、地区横向摸一批上市主体的披露情况
- 已知股票简称或公司全称,想按时间段拉它的公告

不适用:
- 目标不是上市公司 → 公告库里没有,改用 `enterprise_aggregation_summary` 等企业信息工具
- 要工商登记、股东、涉诉、被执行等结构化企业信息 → 走企业信息类工具,别用公告检索代替
- 要裁判文书 → `search_cases_normal` / `search_cases_authority`
- 要法规原文 → `search_laws` / `search_regulations`

输入字段(全部可选,但**至少填一个**,`top_k` 不计入):
- name / jc: 公司全称(子串模糊)、股票简称(精确匹配)
- title / content: 公告标题(空格切分后需全命中)、公告全文检索词
- search_mode: `AND` / `OR`,默认 `AND`,**只作用于 content**
- fbrq_start / fbrq_end: 公告发布日期区间,含当日,YYYY-MM-DD;起不得晚于止
- market: 交易所,精确匹配,只能是 深证A股 / 上证A股 / 北证A股
- area: 地区,精确匹配,取值含"境外""香港",不含"中央/最高"
- zsx_type: 中上协行业分类,子串模糊命中
- top_k: 默认 20,官方上限 50

注意事项:
- **不做本地优先**:本地知识库没有公告这一数据源,同参数缓存命中才返回 0 积分,否则一次 10 积分
- 请求体不能为空 —— 只填 `top_k` 会被官方直接判失败,宿主已提前拦截并报错
- 返回的 content 是**命中片段**,不是公告全文;需要原文看返回里的附件链接
- 公告是公司**自述**,不等于已认定事实。写进材料时注明"据其 X 年 X 月公告披露",不要当作既定事实陈述
- `<CITATIONS>` 标 `type: "company"`,title 写「<公司简称> · <公告标题>」,source 写元典返回的公告标识
- 一次可能命中几十条,精选最相关的 3-5 条讲,不要无脑罗列
