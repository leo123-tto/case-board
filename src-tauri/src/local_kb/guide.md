# CaseBoard 本地法律知识库：检索与维护说明

当前知识库路径：`{{KB_ROOT}}`

> 这不是“把任意 Markdown 丢进目录就全部同等检索”的文件夹。CaseBoard 按材料层级和目录职责选择不同检索方式。

## 检索顺序

1. **精确目录**：已知法规名、条号、案号或企业标识时，先按文件名目录和结构字段查找。
2. **Wiki 导航层**：先检索 `wiki/topics/` 专题入口和 `wiki/sources/` 单篇材料卡片；source 卡命中后沿 `source_path` 回到真实 raw 核验。
3. **Raw 关键词层**：Wiki 不足时，在完整原文中做中文 BM25、标题、法规名和条号检索。
4. **Raw 向量层**：仅当关键词层较弱且问题属于描述型表达时，才对 raw 正文做 embedding 语义补召回。
5. **外部数据源**：上述本地层都不足时，才调用元典或其他外部数据库。为了准确性不设固定付费次数上限，但每次外查前都必须真实跑过本地层。
6. **写回**：外部取得的完整详情先写回 L1 raw；以后相同材料可本地复用。未经复核，不自动冒充已治理的 Wiki 页面。

## 目录与检索方式

| 目录 | 放什么 | CaseBoard 怎么用 |
| --- | --- | --- |
| `raw/notes/` | 法规全文、案例全文、实务文章、OCR 整理稿等原始或近原始完整正文 | 关键词检索 + embedding；法规严格按法条切，普通材料均衡分段 |
| `raw/yuandian-cache/` | CaseBoard 调用元典后的搜索缓存和详情缓存 | 相同参数先命中缓存；只有法规/法条/案例完整详情可作为 raw-like 向量语料，`SEARCH-*` 列表不切向量 |
| `wiki/sources/` | 经过整理的单篇材料卡片，必须用 `source_path` 回链真实 raw | 目录/标题/关键概念/BM25 导航，不重复切向量 |
| `wiki/topics/`、`wiki/index.md` | 问题、场景、专题导航 | 优先给人和 AI 找入口，不切向量 |
| `raw/companies/` | 带查询时间和结构字段的企业档案 | 企业名、统一代码、栏目和新鲜度检索，不切向量 |
| `raw/cases-experience/` | 已提炼的办案经验卡片 | 关键词和标题直接读取，不切向量 |
| `00_ARCHIVE/`、`_inbox/` | 历史备份、迁移回滚材料、待处理过程文件 | 完全排除检索和 embedding |

## 新材料应该放哪里

- 完整法规、案例、文章、OCR 正文：先放 `raw/notes/`，保留标题、来源、日期、版本/时效和完整正文。
- 元典自动写回：由 CaseBoard 写入 `raw/yuandian-cache/`，法规全文另提升到 `raw/notes/`，标记 `kb_level: L1`、`wiki_status: pending_review`。
- 企业资料：放 `raw/companies/`，必须保留查询对象、查询时间、数据来源和关键字段。
- 办案经验：通过案件结案沉淀功能写入 `raw/cases-experience/`，不要混入案件原文件。
- 只有复核并提炼出核心内容、关键概念、真实 raw 回链后，才建立 `wiki/sources/`；同主题材料成簇后再建设 `wiki/topics/`。
- 不要把日志、说明、备份、接口报错页、搜索结果列表或只有标题的空壳当作语料。

## 向量切片规则

- 法规：以“第 X 条”为不可跨越的边界，每条单独切片，并在切片中补法规名/版本上下文；短法条仍保留，不与下一条合并。
- 案例、文章、普通笔记：按约 700 个中文字符均衡分段，孤立短标题/短段与相邻正文合并。
- 建索引前：排除归档、管理页、空壳和错误页；同一法规按条文正文指纹去重，保留实质不同的历史版本；相同 raw 与 API 详情优先保留正式 `raw/notes` 副本。
- embedding 只负责“换一种说法仍能找到原文”的补召回，不负责法规版本、企业时效或精确条号判断。

## 给 AI 的维护边界

- 先确认当前知识库路径和目录层级，再建议或执行维护。
- 结论必须回到真实 raw；Wiki 卡片是导航和提炼层，不代替原文。
- 新抓取材料默认只到 L1 raw；不得自动宣称达到 L2/L3，也不得批量生成空壳 source。
- 不删除 raw，不覆盖人工整理页；批量去重、迁移、删除或重建真实向量索引前先取得用户确认。
- 发现本地缺失且具有长期价值的材料，外查后写回 raw，并标记待 Wiki 复核。

## 外部 AI 怎么读取

- 在 CaseBoard 设置的“知识库”页点击“生成或更新 AI 入口”。系统会创建 `.caseboard/AI-KB-GUIDE.md`、`.caseboard/kb-manifest.json`，并在根目录 `AGENTS.md`、`CLAUDE.md` 中安装可重复更新的引导块。
- Codex、Claude Code、WorkBuddy 等能够访问本机文件的 AI：把知识库根目录作为工作区打开，或把设置页复制出的那句路径指令发给它；AI 会先读统一说明和机器清单，再按规则检索或维护。
- 这不是公网链接，也不会上传材料。外部 AI 必须先获得该本机目录的读取/写入权限；没有文件系统权限的网页聊天无法仅凭路径读取。
- CaseBoard 内置 AI 通过 `get_local_kb_guide` 读取同一份模板；是否允许写入由 CaseBoard 的受控工具和独立开关决定，不能任意操作整个文件系统。
