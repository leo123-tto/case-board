search_laws — 按关键词检索法条内容(返回法条命中列表,不是整部法规全文)

适用场景:
- 用户问「民法典关于违约金的规定」「合同解除的法律依据」等具体法律问题
- 起草起诉状 / 答辩状 / 合同前,先验证某条法律是否真实存在,以及确切条号
- LLM 自己想在 final answer 里引用某条法律前,**必须先用本工具确认条号 + 内容**,杜绝凭印象编条号
- 老板问「某省的地方性法规」「司法解释里关于 X 的条款」(配 xljb_1 + dy)

不适用:
- 想看一部法规的整部目录或全文 → 用 `search_regulations` / `get_regulation_detail`
- 已经知道确切的法规名 + 条号要拿全文 → 直接用 `get_law_article`(更省一次调用)
- 想找案例 → 用 `search_cases_normal` / `search_cases_authority`
- 关键词不准确、想用自然语言描述问题 → 改用 `law_vector_search`(语义检索兜底)

输入字段:
- keyword: 必填,中文关键词；多个词用空格分隔。**不要传整句话**,语义搜走 `law_vector_search`
- search_mode: 可选,`AND` / `OR`,控制空格分词后的组合方式
- fgmc / xljb_1 / sxx / dy / fbbm: 可选,分别过滤法规名、效力级别、时效性、地域、发布部门
- fbrq_start / fbrq_end、ssrq_start / ssrq_end: 可选,YYYY-MM-DD,限制发布或实施日期
- top_k: 可选,返回上限,默认 20,最大 50

注意事项:
- **通常建议每次聚焦一个争点**，避免把多个不相关法律问题塞进同一次检索；如果多个问题确实共用同一规范主题，也可以合并。复合案件可参考拆成“合同生效条件”“未生效返还”“买卖交付违约”“技术资料质量”“履行抗辩”等查询
- **通常优先 `AND`**：把可能共同出现在同一法条里的 1-4 组高区分度规范短语用空格分开，使用 `search_mode=AND`；能判断法律范围时同时填 `fgmc` 和 `sxx=现行有效`。例如“完整 无误 有效 达到约定目标”比整段技术转让纠纷事实更容易精确定位。具体案件中有更合适的查询方式时可以调整
- `AND` 零命中通常表示某个词不是法条原文，先删除最不确定的词或换成规范同义词再查；不要直接改成宽泛 `OR` 制造几十条跨领域噪声。仍不知道规范措辞时再用单争点 `law_vector_search`
- **宿主强制本地优先**:即使模型直接调用本工具，Rust 也会先跑法规全文目录、BM25 和适用的本地向量检索；强命中直接返回本地材料，不会调用元典
- **优先用本地缓存**:相同参数的元典缓存也先于外部请求复用；真正外查 `rh_ft_search` 为 **10 积分/次**。为准确性可以多轮检索，但每轮应改变法规范围、关键词或时点条件
- 外部付费响应保留元典可用字段和正文。默认 `sxx=现行有效`；普通请求若仍返回失效、废止或尚未生效候选，Rust 会在送入模型和缓存前剔除并补检现行替代法源
- 用户明确把 `sxx` 设为非现行状态时，候选可带 `historical_research_only` 保留到结果与缓存，供历史研究；引用时必须标明版本和适用时点，绝不得冒充现行依据
- 命中结果通常包含 ftnum(条号)+ fgmc(法规名)+ content(元典返回正文),LLM 在 final answer 引用时**必须**写完整条号 + 法规名,并把这条命中加入 `<CITATIONS>` 块,标 `type: "law"` + `source: "<元典 id>"`
- 本地各层和外部关键词检索仍不足时，可考虑 `law_vector_search`；为了准确性不设固定付费次数上限，但每次重查应有新的检索目标、条件或交叉核验理由。连续两次没有新增高价值法源可作为暂停该分支、改写争点的信号；存在新目标或核验理由时仍可继续
