# 工作流架构 · 律师人机协同四轨四门禁体系

## 一张图

```
用户任务
  ↓
四轨分流（按触发词 + 任务复杂度自动路由）
  ↓
┌─ 轨道一（快速通道）→ 5步确认 → 初步判断（72h有效）
├─ 轨道二（报价）    → 八阶段 → 服务方案/报价书
├─ 轨道三（尽调）    → 六阶段 → 三段式报告+风险清单
└─ 轨道四（正式案件）→ 四道门禁 → 正式交付物草案
                    │
                    ├─ Gate 1: extraction-agent（只搬不分析）
                    ├─ Gate 2: verification-agent（找矛盾找漏洞）
                    ├─ Gate 3: reasoning-agent + opposing-counsel-agent + dispatcher
                    └─ Gate 4: delivery-agent（组装+自检）
                              │
                    delivery_gate（五门禁+通用补充G1-G6+领域补充）
                              │
                    十一项一致性 + 律师确认 + VIE三层校验
                              │
                    正式交付物草案（标注 lawyer-confirm）
```

## 设计原则

不把全部规则静态塞进上下文，按**任务类型 + 执行阶段**动态组装。每项任务仅加载必需的规则子集，无关规则直接排除，减少上下文污染。对标 ACE 活页手册模式——上下文是一本不断演化的活页手册，而非一段越写越长的 prompt。

## 加载三层（动态装配）

| 层级 | 含义 | 判定逻辑 |
|---|---|---|
| 🔴 强制加载 | 当前任务类型/阶段必须加载，不可跳过 | 全局硬约束对所有任务强制 |
| 🟡 条件加载 | 满足特定条件时加载 | 按任务阶段 + 案件类型逐项判定 |
| 🟢 禁止加载 | 当前任务类型明确排除 | 类型确定时从严排除 |

## 四轨分流路由表

| 轨道 | 触发词（代表性） | 执行引擎 | 产物 | 时效 |
|---|---|---|---|---|
| **轨道一·快速通道** | 快速/紧急/初步判断/格式检查/纯翻译/单一法条查询 | `litigation-support-advisor` skill | 初步判断 + A类内部底稿 | 72h |
| **轨道二·法律服务报价** | 报价/服务方案/投标/收费标准/律师费报价/年度顾问费 | `rules/80_pricing_proposal.md`（八阶段） | 服务方案/报价书 | — |
| **轨道三·非诉尽调** | 尽调/数据室/并购审查/合规尽调/税务尽调/劳动用工尽调 | `rules/70_due_diligence.md`（六阶段） | 三段式报告+风险清单 | — |
| **轨道四·正式案件（默认）** | 起诉状/答辩状/代理词/质证意见/合同纠纷/刑事等 | 四道门禁完整管线 | 正式交付物草案 | — |

## 轨道间桥接规则

- 紧急场景可降级，但须标注降级原因和流程缺失项
- 尽调中发现需正式法律意见→自动切换轨道四
- 双关键词冲突的复合场景按对应轨道桥接规则裁决

## Agent 行为四原则

| # | 原则 | 核心纪律 |
|---|---|---|
| 1 | **先思后行** | 不确定时先列假设不沉默；遇到歧义列出多种解读；事实不清时暂停并指明信息缺口 |
| 2 | **简洁优先** | 产出长度与任务复杂度匹配；500 字说清就不写 2000 字 |
| 3 | **精准改动** | 增量补提只碰指定维度；修改已生成交付物只改被指出部分 |
| 4 | **目标导向** | 从最终交付物反向审视每一步必要性；阶段转换检查=目标达成确认 |

## 通用底线（P0-P1，不可协商）

- 所有事实必须有材料出处；不替律师拍板
- 不臆造法条、案例、案号、当事人、金额
- 法律适用/证据采纳/策略/定稿一律标注 `lawyer-confirm`
- `[civil]` 以《民法典》及最新司法解释为首要依据
- `[criminal]` 以《刑法》及最新司法解释为首要依据
- `[all]` 法规引用以案件对应领域的最新现行有效规范为准
