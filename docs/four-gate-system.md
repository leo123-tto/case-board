# 四道门禁质量保障体系

## 门禁依赖链

```text
                        ┌─ opposing-counsel-agent ─┐（可与 Gate 4 并行）
                        │                          │
Gate 1 提取 → Gate 2 核验 → Gate 3 推理 → Gate 4 交付
    ↑            ↑             ↑             ↑
 依赖：无    依赖：Gate 1   依赖：Gate 2   依赖：Gate 3
             完工并通过      完工并通过     完工并通过
```

## 生命周期钩子（7 个）

每个门禁阶段定义 before/after 钩子自动校验产物的完整性与一致性：

| 钩子 | 触发时机 | 校验动作 | 失败处理 |
|---|---|---|---|
| `after:gate1` | Gate 1 完工后 | Schema 校验（6项：材料索引/掌握程度声明/提取表列完整性/禁止模式/全量提取铁律） | 回退 Gate 1 补提 |
| `before:gate2` | after:gate1 通过后 | 确认 Gate 1 产物齐全：材料索引全覆盖 + 提取表主表 + 材料掌握程度声明 | 缺失项阻塞 |
| `after:gate2` | Gate 2 完工后 | Schema 校验（11项：矛盾清单/疑点清单/可信度分级/外部主体核验/引用案例风险扫描等） | 回退 Gate 2 补核 |
| `before:gate3` | after:gate2 通过后 | 确认 Gate 2 产物齐全：矛盾清单+疑点清单+可信度分级+外部主体核验表+引用案例风险扫描表 | 缺失项阻塞 |
| `after:gate3` | Gate 3 完工后 | Schema 校验（5张表：事实推理/法律适用/P-F-C/要件事实/策略） | 回退 Gate 3 补全 |
| `before:gate4` | after:gate3 通过 + Logic Doctor 通过后 | 输入验收：推理四表齐全 + P-F-C链覆盖 + 四视角审查覆盖 + Logic Doctor通过 | 缺失项阻塞 |
| `on:error` | 任一回退≥3次 | 汇总失败钩子记录 → 升级通知律师 | — |

**执行铁律**：钩子按顺序依次触发，不可跳步。单阶段回退上限 3 次——超限触发 `on:error` 升级。通过后的钩子写入审计日志，未通过的写入 `memory/unresolved.md`。

## Gate 1 · 提取（只搬不分析）

**纪律**：从材料中按预定维度结构化提取信息，禁止任何分析/判断/定性。

### 提取四要素
| 要素 | 含义 |
|---|---|
| 提取目标 | 一句话说清"抠什么出来" |
| 提取维度 | 分几大类（当事人/时间/金额/证据等） |
| 输出格式 | 表格/列表/时间线，明确结构 |
| 来源标注 | 每条产物可回溯到文件名+页码，原文摘录≥20字 |

### 全量提取铁律 6 条（P0 级门禁）

1. 全部材料逐份、逐页、逐段完整提取，海量材料不是跳过的理由
2. 每份材料提取前先建索引（文件名 | 页数 | 格式 | 可读性 | 状态）
3. 每条事实可追溯到具体文件+具体页码，无法标注来源=不存在
4. 材料索引中每份标注「已提取」才算完成
5. 无法处理/缺失/遮蔽/多版本的信息逐项列明
6. 6 条全部通过方可放行 Gate 2

### 提取放行前自检 6 项
材料全覆盖 / 逐份提取记录 / 技术障碍声明 / 页码覆盖 / 来源可追溯 / 信息完整性

### 提取输出契约
```
| 维度 | 内容摘要 | 来源(文件+页) | 原文摘录(≥20字) | 备注 |
```
备注仅记客观事实（如"OCR识别度低"），不记主观判断。字段缺失统一写"未载明"或"待核验"。

### 增量补提模式
后续阶段发现需补充某类事实时，仅针对指定维度补提，标注 `[增量补提]` + 触发来源 + 日期。补提产物与原始产物合并，不覆盖原始产物。

## Gate 2 · 核验（找矛盾、找漏洞、找佐证）

**原则**：只列客观矛盾，不做法律归因。法律层面的判断留给 Gate 3。

### 三层矛盾分析

| 层次 | 内容 |
|---|---|
| **第一层：对方证据内部矛盾** | 同一主体在不同时间/场合的陈述是否冲突；同一文件内部数据是否前后矛盾 |
| **第二层：对方说法与其证据矛盾** | 答辩状主张 vs 证据支撑；专家意见 vs 基础数据 |
| **第三层：我方与对方证据矛盾** | 对同一事实的相反描述/不同解读/相反定性依据 |

### 矛盾强度三级标注

| 强度 | 标注 | 典型特征 |
|---|---|---|
| ★ 致命 | ★ | 对方证据直接反驳对方主张 |
| ◆ 重要 | ◆ | 双方证据不一致，但各有支撑 |
| ○ 一般 | ○ | 存在不一致但对方可能有合理解释 |

### 三类来源核验

```
事实层（本地资料）→ 规则层（知识库）→ 市场层（外部检索）
```

本地资料必须先行。外部检索默认关闭，仅在任务明确允许时启用。

### 核验专项能力

- **法规标准有效性专项核验**：逐项核验每一条引用的法律/法规/司法解释/标准的现行有效性，标注核验方式与结果
- **外部主体信用自动查询**：非自然人主体自动触发，四级递进查询路径（国家企业信用信息公示系统→中国执行信息公开网→第三方平台→关键人员穿透）
- **引用案例全文风险扫描**：三层扫描（效力核验/不利认定扫描/风险评级），致命级案例一律不得引用
- **知识库四步交叉引用协议**：路由规则加载→概念检索→原始数据源检索→外部补充

### 核验输出契约
- 核验范围声明（材料覆盖/核验方式/抽样验证/无法核验事项）
- 矛盾清单 + 疑点清单 + 事实可信度分级（高/中/低/待核验）
- 我方风险交叉核查表

## Gate 3 · 推理（事实→法律适用→策略）

**核心定位**：AI 列选项+给代价，人选哪个+担后果。

### 推理四表

| 表名 | 内容 | 谁审 |
|---|---|---|
| **事实推理表** | 从提取产物推断事实结论 | 律师随机抽检 3-5 条，逐条回溯原文 |
| **法律适用推理表** | 案由定性/构成要件比对/类案检索 | 法条现行有效性+构成要件完整性+类案匹配度 |
| **要件事实表** | 规范→要件→本案事实→证据→是否满足 | "是否满足"仅限：满足/不满足/证据不足/待核验 |
| **策略推理表** | 至少 2-3 个选项 + 各自代价 | 不下结论，全部标注 `lawyer-confirm` |

### P-F-C 三段论链

每个法律结论可回溯到三段论结构：
```
P（大前提·法律规则）→ F（小前提·本案事实）→ C（结论）
标注：中项 | 有效性 | 可废止条件
```

### 四视角对立审查

| 视角 | 内容 |
|---|---|
| **视角 1：对方律师/公诉人** | 7 维度红队扫描：事实攻击/证据攻击/法律解释攻击/程序攻击/因果链攻击/金额攻击/策略攻击 |
| **视角 2：审判法官** | 7 维度心证预判：争议焦点识别/证据采信预判/法律适用预判/心证形成/判决可上诉性/程序效率/释明影响 |
| **视角 3：监管/行业主管** | 涉及监管合规时启用 |
| **视角 4：上诉审法官** | 存在一审判决时启用 |

### S×L 风险评级矩阵

5 档严重度（S5灾难性→S1微小）× 4 档可能性（L4极高→L1较低）= 20 格行动矩阵：

| | L1(较低) | L2(中等) | L3(较高) | L4(极高) |
|---|---|---|---|---|
| S5 | 监控 | 标注+律师审查 | 标注+律师审查 | **紧急律师审查** |
| S4 | 监控 | 标注+律师审查 | 标注+律师审查 | 标注+紧急审查 |
| S3 | 记录 | 监控 | 标注+律师审查 | 标注+律师审查 |
| S2 | 记录 | 记录 | 监控 | 监控 |
| S1 | 记录 | 记录 | 记录 | 记录 |

### 期限不可逆性检测

以下期限错过后果不可逆，至少标注 `[review: 律师确认]`：
- 诉讼时效（剩余≤90天→标注；≤30天→⚠️紧急）
- 上诉期（判决15日/裁定10日，收到即标注）
- 举证期限（剩余≤7天→⚠️紧急预警）
- 财产保全续封（到期前30天→续封预警；前15天→S5）
- 申请鉴定期间（同举证期限）

### 不确定性升级规则（5 个触发阈值）

任一触发即不给结论：核心材料缺失/法律空白或各地裁判不一/错误不可逆/AI知识边界/结论高度依赖具体事实

### 类案研究

- **决定性事实变量提取**：提取 8-12 个可能影响裁判结果的事实变量，逐项打分匹配度
- **五维度加权评估**：法律关系(30%)/争议焦点(25%)/关键事实(25%)/裁判规则(15%)/程序关联(5%)
- **八项排序规则**：级别相近优先 > 专业相近优先 > 时间相近优先

### Logic Doctor 五维自检（Gate 3→4 过渡层）

一、法条准确性（真实存在+条文号正确+现行有效）→ 二、逻辑连贯性（五步完整+推理链无断档）→ 三、时效性（诉讼时效+上诉期+除斥期间+法律版本）→ 四、实务可行性（管辖法院+证据要求+程序路径）→ 五、合规性（免责声明+未做胜诉承诺+AI痕迹可清除）

## Gate 4 · 交付（组装+自检）

**核心定位**：不是"写"，是"组装+自检"。AI只负责把硬数据填进模板占位符，不负责创造内容。

### 生成前必挂 4 件
| 必挂件 | 缺失后果 |
|---|---|
| 模板 | AI 按它"以为"的格式写，结构失控 |
| 前序产物（Gate 1+2+3 全部产出） | AI 缺数据就脑补 |
| 受众定义（A/B/C/D 四类） | 口径错位 |
| 质量标准（十一项一致性+律师确认） | 自检缺位，带病交付 |

### 受众四类适配过滤

| 类型 | 受众 | 核心规则 |
|---|---|---|
| **A 类** | 内部律师/法务 | 100%透明度，完整红队报告，所有弱点/假设/开放问题 |
| **B 类** | 客户/管理层 | 浓缩为"主要风险"，法律术语翻译为通俗语言，一页纸总结 |
| **C 类** | 对方律师 | 最小披露——删除全部红队扫描/策略退路/不利事实完整清单/AI来源标签 |
| **D 类** | 法院/仲裁庭 | 格式合规+论证完整性+无AI痕迹+证据编号一致性+法条引用准确性+自认风险检查 |

### VIE 三层校验

- **第一层·输入校验**（生成前）：占位符全部填充 + 前序产物齐全 + 模板四件到位
- **第二层·生成后校验**（生成后立即执行）：残留占位符零容忍 + 格式完整性 + 引用一致性 + 受众口径匹配
- **第三层·校验报告**（自动生成）：逐项列出检查项和通过状态，未通过项标注严重度和修复措施

### 通用补充门禁 G1-G6

| 门禁 | 内容 |
|---|---|
| **G1 案例白名单** | 引用案例是否有公开URL/案号可查证 |
| **G2 法规有效性** | 全部引用是否经过现行有效性核验 |
| **G3 VIE三层校验** | 生成→自检→报告 三层是否完整 |
| **G4 发送前适配** | 受众口径适配检查（C/D类文件未执行→block） |
| **G5 五维引用审计** | 真实性/效力/支持度/完整性/可追溯性五项逐条检查 |
| **G6 提交前独立复核** | C/D类+≥3个争议焦点时触发独立 opposing-counsel 复核 |

### 十一项一致性自检

事实一致性 / 引用一致性 / 金额/时间/人名一致性 / 法条引用 / 类案引用 / 经济分析数据 / 术语对照 / 逻辑链条 / P-F-C链可回溯 / 结论未过度超出证据范围 / 受众口径

### 交付四档结果
| 结果 | 含义 |
|---|---|
| `pass` | 全过，进入律师审阅 |
| `review` | 部分待核验但不影响整体，标注后交律师判断 |
| `fail` | 一致性失败，必须返工 |
| `block` | 命中 critical 硬规则，立即停止 |
