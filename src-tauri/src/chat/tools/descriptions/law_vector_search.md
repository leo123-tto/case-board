law_vector_search — 用自然语言语义检索法条(关键词检索不准时兜底)

适用场景:
- 用户用一整句话或一段描述问问题,关键词不明确(如「物业擅自处分业主财产构成什么」)
- 本地目录、BM25、embedding 和一次必要的外部关键词检索仍不足时，再用本工具做外部语义补检
- 找「跟某行为类似但法条措辞不同」的条款,如「擅自处分」语义近的条款用词可能是「无权处分」「越权代理」等
- 想找的法条核心词比较生僻,关键词检索可能漏

不适用:
- 用户给出明确关键词 → 优先 `search_laws`(更快、更准)
- 已知条号 → `get_law_article`
- 想找案例 → `case_vector_search`(案例的语义搜)

输入字段:
- query: 必填,通常建议描述**一个尚未解决的争点**的自然语言问题,不是关键词；整段复合案情往往噪声较高，但模型判断整体语义检索更合适时也可以使用
  - 好例子:「业主把车位转租给第三人,物业能否单方收回」
  - 坏例子:「车位 转租」(这种关键词请用 `search_laws`)
- rewrite_flag: 可选,默认 true,让元典改写检索问题；实测聚焦争点时开启改写通常比关闭覆盖更好
- fatiao_filter.sxx / effect1: 可选数组,过滤时效性和效力等级
- fatiao_filter.law_start / law_end: 可选,YYYY-MM-DD,限制实施日期
- return_num: 可选,默认 45,最大 50

注意事项:
- 可先把案情拆成争点并分别完成本地检索，再用语义检索补仍缺法规名或规范措辞的缺口。它通常更适合发现候选法源；具体是否整案检索、如何拆分，由模型结合任务自行判断
- `fatiao_filter.sxx` 未填写时 Rust 默认补为 `["现行有效"]`；能判断时把 `effect1` 限定为“法律”“司法解释”等必要层级。返回后按相关性逐条判断，不因语义相似就直接引用
- **宿主强制本地优先**:Rust 会重新核验法规目录、BM25 和本地 embedding；本地强命中时直接返回，不调用元典
- 本地不足时可按准确性需要与 `search_laws`、`search_regulations` 组合多轮检索；每轮宜有不同的语义目标或筛选条件。连续两次没有新增高价值法源可作为回到争点拆解的信号；存在新目标、时点或交叉核验理由时仍可继续
- 优先用本地缓存(法条永久缓存)
- 返回结构通常为顶层 `extra.fatiao[]`（同时兼容旧形状 `data.extra.fatiao[]`），每条带 `score`(语义相似度)
- 语义检索的命中可能比关键词检索更宽,LLM 拿到后**必须**结合上下文判断相关性,不要无脑全用
- 外部付费响应保留候选和 content，不做预览截断。默认只保留现行有效；用户明确在 `fatiao_filter.sxx` 选择非现行状态时，历史候选可带 `historical_research_only` 返回，引用必须标明版本、适用时点和非现行状态
- `<CITATIONS>` 标 `type: "law"`,title 写「<fgmc> 第 <ftnum> 条」
- 积分消耗同 `search_laws`(本地命中 0，在线 10)
